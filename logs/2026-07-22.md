## 🔁 Loops de estudio

### Loop 1 ✅ — Dometrain: "Building Command Handlers" (cap. 12) — visto y consolidado
- **Curso:** Event Sourcing con Marten & .NET (Dometrain) · cap. 12. La lección más larga/compleja del capítulo.
- **`StoredEvent`** (record): metadatos de persistencia — `AggregateId`, `SequenceNumber`, `Timestamp` (DateTime UTC), `object EventData`. Dentro del aggregate el evento es solo `object`; al persistir necesita saber a qué aggregate, orden y cuándo.
- **`IEventStore`** (interfaz): `GetEvents(aggregateId)` · `AppendEvent(storedEvent)` (prefijo `app`, `event` es reservada) · `SaveChanges()` como **unit of work**.
- **`EventStream<TEntity>`** (`where TEntity : AggregateRoot, new()`): `GetEntity()` = fetch todos los eventos → `new TEntity()` → `foreach` aplicando `entity.Apply((dynamic)e.EventData)` (el cast a dynamic elige el overload correcto; si no, iría al `Apply(object)` vacío) + guarda `lastSequenceNumber`. `Append(obj)` = `++seq`, crea `StoredEvent(id, seq, UtcNow, data)`, `store.AppendEvent`.
- **`CommandHandler<TCommand>`** (abstract, primary ctor con `IEventStore`): `abstract Handle(TCommand)` + `protected GetStream<TEntity>(Guid id)`. NO mapear genéricamente command→entidad (fricción); cada handler pide su stream.
- **Ejemplo `AddShippingLabelHandler`:** `GetStream<Box>(command.BoxId).GetEntity()` (dispara replay) → `if (command.Label.IsValid())` append `ShippingLabelAdded` else append `ShippingLabelFailedToAdd(FailReason.TrackingCodeInvalid)`. Los value types brillan aquí.
- **Clave:** el handler **NO guarda** — `SaveChanges()` se hace en el **command router**, para poder **encadenar handlers en una sola transacción**.
- **Validación (3/3):** (1) `SaveChanges()` fuera del handler → el **router encadena varios handlers en una sola transacción** (atómica); (2) el `(dynamic)` resuelve el overload de `Apply` en runtime según el tipo real, sin él enlaza al `Apply(object)` vacío y no reconstruye estado (= su bug del workshop, del otro lado); (3) `SequenceNumber` fija el orden de replay, y se lleva `lastSequenceNumber` para asignar `last+1` al append (base también de concurrencia optimista).

### Loop 2 ✅ — Dometrain: "Adding a Command Router" (cap. 13) — visto y consolidado
- **Curso:** Event Sourcing con Marten & .NET (Dometrain) · cap. 13.
- **Por qué el router:** `SaveChanges` no va en el handler para permitir **composabilidad** (descomponer un command complejo en varios pequeños, ejecutar sus handlers, y un solo `SaveChanges` al final). El **router** orquesta: localiza el handler → lo ejecuta → `SaveChanges()`.
- **Scope:** el router necesita el `IEventStore` del **mismo scope** para que `SaveChanges` opere sobre la **misma instancia** que usó el handler.
- **Enfoque 1 (switch):** `switch(command)` con un `case` por tipo, `new XHandler(eventStore).Handle(cmd)`, `default` → throw. Funciona pero la clase crece y se ensucia si un handler necesita **deps extra** (habría que inyectarlas también en el router).
- **Enfoque 2 (reflection + DI, el de Boyne):** inyecta `IServiceProvider` (mismo scope → misma instancia de store). ~5 líneas de reflexión: tipo del command → construir `CommandHandler<T>` → `GetService` (handler con sus deps resueltas por DI) → `MethodInfo` de `Handle` → invoke → `SaveChanges()`.
- **Resultado:** el command router es el **único punto de interacción con el dominio** (se enchufa a APIs). Registrar store + handlers → lanzarle commands.
- **Validación (1.5/3):** P2 ✅ (SaveChanges fuera del handler = unit of work + composabilidad → encadenar handlers, un solo save). **P1 ⚠️ corregida:** el store scoped acumula appends en memoria; si el router hace `SaveChanges` sobre **otra instancia** distinta a la del handler, esa instancia no tiene los eventos → **no persiste nada (se pierden)** — NO es tema de orden. Mismo scope = misma instancia. **P3 ⚠️ matizada:** el problema real que resuelve reflection+DI no es "un case por comando" (secundario) sino la **inyección de dependencias** de cada handler (con switch habría que inyectar las deps extra también en el router → constructor mess).
- **Payload NotebookLM:** `.sync/notebooklm_outbox/2026-07-22_adding-a-command-router.md`.
